# Contributing

Open Course Map is a hand-drawn map of free university courses. Most
contributions are one of three things: a course that belongs on the map, a fix
to one already there, or a bit of code. This page covers all three, and how
releases work at the end.

## What belongs on the map

A course belongs on the map when it is:

- **A full lecture series**, recorded and posted by the university or the
  lecturer — OCW, a department channel, a lecturer's own playlist. Open series
  from labs and companies (DeepMind, fast.ai) count when they are taught like a
  course.
- **Free to watch**, on YouTube or another public host, with no login.
- **Ideally with an official course page** — syllabus, schedule, problem sets —
  because that is where prerequisites come from.

Partial playlists are fine — a run with half the lectures, audio only, or
excerpts — as long as the version label says so: `(selected lectures)`,
`(audio only)`, `(excerpts)`, `(partial)`. An honest label beats a silent gap.

Not on the map: platforms that need a sign-up, single talks, tutorial
channels, and paid courses.

## How the data is laid out

Everything is plain JSON under [`src/data/`](src/data). [`src/types.ts`](src/types.ts)
is the schema — every field is documented there. Nothing validates the JSON at
build time, so read it.

| File | What it holds |
| --- | --- |
| `fields.json` | The atlas: every field and subject group with its box on the map, plus the edges and ghost cards that cross subjects |
| `subjects/<id>.json` | One subject's courses and the edges between them. The filename is the subject id and must match a group in `fields.json` |
| `pathways/<id>.json` | An ordered sequence through courses that already exist in a subject |
| `views/<playlistId>.json` | Per-lecture view counts, generated by `scripts/fetch-views.py` — never edited by hand |

## Adding a course

1. **Check it isn't already there.** Search `src/data/subjects/` for the course
   number and the playlist id. The same course from another year or lecturer
   is a new **version** on the existing card, not a new card. A course that
   is already on the map but also belongs in view on another subject page gets
   a **ghost** there (`ghosts` in `fields.json`), not a copy.

2. **Pick the subject.** Open its file. If the course fits no subject in its
   field, it goes in that field's `Other` box (`cs-other`, `physics-other`,
   `chem-other`, `bio-other`, `other`) — that is what those are for.

3. **Add the entry.**

   ```json
   "mit-560": {
     "title": "5.60 Thermodynamics & Kinetics",
     "university": "MIT",
     "level": "undergrad",
     "pos": { "x": 780, "y": 120 },
     "versions": [
       {
         "label": "MIT 5.60 · Bawendi & Nelson · Spring 2008",
         "url": "https://ocw.mit.edu/courses/5-60-thermodynamics-kinetics-spring-2008/",
         "youtube": "https://www.youtube.com/playlist?list=PL...",
         "date": "Spring 2008",
         "youtubeId": "...",
         "primary": true
       }
     ]
   }
   ```

   - **id** — `<school>-<course number>`, lowercase: `stanford-cs229`,
     `yale-chem125a`.
   - **title** — course number and name as the school writes it. Cards wrap
     the title at about 26 characters a line, two lines, then an ellipsis, so
     keep it short and use `CODE · Name` when it needs a clean break
     (`PHYS 200 · Physics I`). Look at the card once it renders.
   - **university** — reuse the exact string if the school is already on the
     map (`MIT`, `UC Berkeley`, `ETH Zürich`, …); it is the key that finds the
     logo. A new school is fine without a logo — the card shows the name.
   - **level** — `undergrad` or `grad`, as the school classifies it. Leave it
     out for open series that have no level.
   - **pos** — where the card sits on the subject page. Cards are 220×168 and
     pages use a grid: `x` = 80, 430, 780, 1130, … and `y` = 120, 420, ….
     Take the next free slot, or the one that puts it beside the courses it
     relates to.
   - **versions** — one per recording of the course. `label` is
     `School Code · Lecturer · Term`; `url` is the official course page;
     `youtube` the playlist; `youtubeId` any video id from it (it makes the
     thumbnail). Mark exactly one `primary`.
   - **textbooks** — only when the course has an unambiguous assigned text
     across all its versions. See `Textbook` in `types.ts`, and
     [`public/covers/README.md`](public/covers/README.md) for cover images.

4. **Draw an arrow only when you can source it.** Prerequisites come from the
   course page or syllabus, not intuition. Within a subject, add to that
   file's `edges`; across subjects, add to `edges` in `fields.json` and place a
   ghost of the prerequisite on the subject page so the arrow has something to
   land on. If you can't source it, draw nothing — put the cards side by side
   in the order you would take them.

5. **Snapshot the views.** `python3 scripts/fetch-views.py` writes
   `src/data/views/<playlistId>.json` for every playlist on the map, standard
   library only, no API key. It refetches all of them, so stage only the new
   file(s) — refreshing everyone else's numbers is its own commit.

6. **Look at it.** `npm run dev`, open the subject page, and check that the
   card sits inside its box, the title wraps, the thumbnail loads, and any
   arrow points the right way. Then `npm run build`, which type-checks the code
   and must pass.

7. **Open a PR** — one course, or one tightly related batch, per PR, with the
   course page and playlist linked in the description. Commit messages are
   imperative and say what changed: `Add MIT 5.60 Thermodynamics to Physical
   Chemistry`.

If you would rather not touch JSON,
[suggest the course in an issue](https://github.com/mannmalviya/open-course-map/issues/new?template=suggest-a-course.yml)
with the links and it will get added.

## Fixing what's there

Dead links, a better playlist, a wrong or missing prerequisite, a mislabelled
version, a course in the wrong subject — all welcome as PRs or issues. For a
prerequisite, link the syllabus that says so.

## Pathways

A pathway (`src/data/pathways/<id>.json`) is a sequence through courses already
on the map. `official` pathways are transcribed from a department's own
requirements and cite them in `source`; `curated` ones are a personal pick and
say so. A step a department requires that nobody has posted online goes in
`gaps` rather than being skipped, so the sequence stays faithful. Open an issue
before starting one so the shape can be agreed on.

## Logos and covers

- School marks: [`public/logos/README.md`](public/logos/README.md). A new
  school gets a logo when a clean SVG exists on Wikimedia Commons; otherwise
  the name is fine.
- Book covers: [`public/covers/README.md`](public/covers/README.md).

## Code

React + TypeScript + Vite, with rough.js drawing the map. There is no test
suite; `npm run build` is the check. Small fixes are welcome as PRs. For
anything that changes how the map looks or works, open an issue first — the
hand-drawn look and the pan-and-place layout are deliberate, and it is easier
to talk about a change before it is built.

## Releases

`main` deploys to [open-course-map.vercel.app](https://open-course-map.vercel.app)
on every push, so the site is always current and a tag is a milestone, not a
deploy. Tags mark the points worth a "what's new": a new field, a pathway, a
visible feature, or a sizeable batch of courses — not every push.

Versions are `vMAJOR.MINOR.PATCH`: `MINOR` for a new field, pathway or feature;
`PATCH` for courses and fixes batched since the last tag; `v1.0.0` when the
core fields are covered well enough to announce. To cut one:

```sh
npm version minor -m "Release v%s"   # bumps package.json, commits, tags vX.Y.Z — needs a clean tree
git push --follow-tags
gh release create vX.Y.Z --title vX.Y.Z --notes-file notes.md
```

The notes are two lines on what changed, then the commit list from
`git log --oneline vPREV..vX.Y.Z` — commit messages here are written to read
as a changelog.
